# IoMT Telemetry Payload Specification

## 1. Overview

This document defines the fixed-size binary payload structure for IoMT
telemetry data used in the encryption and Zero Trust experiments.

The payload is intentionally minimal and deterministic so that AES-GCM
encryption performance can be measured using a fixed plaintext size.

Each telemetry record is exactly **12 bytes**.

The payload is serialized using **Big-Endian (Network Byte Order)**.

---

## 2. Payload Structure

Each payload represents one telemetry snapshot at a target frequency of
**1 record per second (1 Hz)**.

| Offset | Field | Size (Bytes) | Data Type | Description / Unit |
|---:|---|---:|---|---|
| 0 | `timestamp` | 4 | `uint32` | Unix epoch time in seconds |
| 4 | `heart_rate` | 1 | `uint8` | Mock heart rate, BPM |
| 5 | `skin_temp` | 2 | `int16` | Skin temperature, °C × 100 |
| 7 | `eda_value` | 4 | `float32` | EDA value in µS |
| 11 | `status_flag` | 1 | `uint8` | Device status bitmask |

**Total Payload Size: 12 Bytes**

---

## 3. Field Encoding

### 3.1 Timestamp

`timestamp` is encoded as an unsigned 32-bit integer.

```text
uint32

The value represents Unix epoch time in seconds.

3.2 Heart Rate

Heart rate is represented as an unsigned 8-bit integer.

uint8

For the current prototype, heart rate is generated as mock telemetry.

The BVP signal is not converted into a medical-grade heart-rate
measurement.

The purpose of this field is to provide a realistic telemetry field for
testing binary serialization and encryption performance.

3.3 Skin Temperature

Skin temperature is represented as a signed 16-bit integer.

int16

The encoded value is:

encoded_temperature = temperature_celsius × 100

Example:

36.52 °C → 3652

The source value is obtained from WESAD S2 after conversion to the target
1 Hz representation.

The exact WESAD source field and sampling rate must be verified before the
IoMT generator is implemented.

3.4 EDA

EDA is represented using IEEE-754 32-bit floating-point format.

float32

One representative EDA value is selected for each one-second interval.

The EDA value is retained in numeric form rather than converted to an
integer.

3.5 Status Flag

status_flag is an unsigned 8-bit bitmask.

uint8

Example:

0x01 = Mock heart-rate field active

Additional status bits may be defined later if required by the prototype.

4. Data Alignment

The source WESAD signals have different native sampling rates.

For the IoMT prototype, all telemetry records are represented at:

1 Hz

One record therefore corresponds to one one-second interval.

The downsampling method must be deterministic and documented so that the
same source data produces the same telemetry records.

For the current prototype:

EDA is reduced from its native sampling rate to 1 Hz.
Skin temperature is reduced from its native sampling rate to 1 Hz.
BVP is not used to calculate medical-grade heart rate.
Heart rate is generated by the mock telemetry generator.
5. Number of Test Records

The initial encryption benchmark dataset contains:

1,000 records

Each record contains:

12 bytes

Therefore, the plaintext input size before encryption is:

1,000 × 12 = 12,000 bytes

This dataset is intended for:

binary serialization testing
AES-GCM encryption testing
encryption/decryption correctness testing
throughput and latency benchmarking
Zero Trust communication experiments

It is not a machine-learning training dataset.

6. Serialization

Python's struct module is used to serialize each telemetry record.

The required format is:

">IBhfB"

The format represents:

>   Big-Endian
I   uint32 timestamp
B   uint8 heart_rate
h   int16 skin_temp
f   float32 eda_value
B   uint8 status_flag

The resulting binary payload must always have:

struct.calcsize(">IBhfB") == 12

No padding bytes should be introduced.

7. Serialization Pipeline

The prototype follows:

WESAD S2
    |
    v

    |
    v

9. Validation Requirements

Before AES-GCM benchmarking begins, the payload generator must verify:

Exactly 1,000 records are generated.
Every record contains all required fields.
Every serialized payload is exactly 12 bytes.
Serialization is deterministic.
A serialized payload can be decoded back to the original fields.
Big-Endian byte ordering is preserved.
No unexpected padding bytes are present.

The payload size must be checked programmatically using:

assert struct.calcsize(">IBhfB") == 12
10. Scope Boundary

This payload specification is part of the IoMT security experiment.

The following WESAD/ML components are currently outside the active
pipeline:

Windowing
Feature Extraction
Stress Classification
Model Training
Model Evaluation

The current research pipeline begins at the telemetry representation and
focuses on:
