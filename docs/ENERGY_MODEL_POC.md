# Energy Model Proof-of-Concept

## Purpose

This document records the small-scale proof-of-concept (PoC) for the
IoMT mathematical energy model.

The purpose of this PoC is to verify that the system can:

1. encode the same telemetry records using JSON, CBOR, and Custom Binary;
2. measure the actual payload size produced by each encoder;
3. construct the corresponding AES-256-GCM Secure Packet;
4. use the measured processing time and transmitted packet size as inputs
   to the energy model; and
5. produce processing energy, transmission energy, and total energy in mJ.

This is a feasibility test only. It is not the final statistical
experiment described in the research methodology.

## Energy Model

The model is:

```text
E_total = E_process + E_tx

Processing energy:

E_process = V × I_cpu × T_process

Transmission energy:

E_tx = V × I_tx × T_tx

Transmission time:

T_tx = L / R

where:

V = supply voltage (V)
I_cpu = CPU current during processing (A)
T_process = processing time (s)
I_tx = transmission current (A)
L = actual transmitted Secure Packet size (bit)
R = transmission rate (bit/s)

The energy result is converted from Joule to millijoule:

E(mJ) = E(J) × 1000

The Secure Packet overhead is:

4 Device_ID
+ 4 Sequence_Number
+ 12 Nonce
+ 16 Authentication_Tag
= 36 bytes

Therefore:

Secure Packet size = Payload size + 36 bytes

For the 12-byte Custom Binary payload:

12 + 36 = 48 bytes
Measurement Procedure

For each format, the script uses the same 1,000 telemetry records.

The processing flow is:

Telemetry records
    ↓
Payload encoding
    ↓
Measure actual payload size
    ↓
AES-256-GCM encryption
    ↓
Construct Secure Packet
    ↓
Measure processing time
    ↓
Calculate transmission time
    ↓
Calculate energy
    ↓
Save results

The processing time used in this PoC is the measured encoding time plus
the measured AES-256-GCM encryption time for the same records.

The transmission energy uses the actual Secure Packet size rather than
the plaintext payload size.

Interpretation

The PoC demonstrates that the energy-model calculation pipeline works
with measurements generated by the actual payload encoders and
AES-256-GCM packet construction used in the prototype.

The transmission energy is calculated from the total Secure Packet size,
which includes both payload and fixed security/protocol overhead.

In this PoC, the 12-byte Custom Binary payload produces a 48-byte
Secure Packet after adding the fixed 36-byte overhead.

These values are development-environment measurements and should not be
interpreted as measurements of physical battery consumption on an actual
nRF52832 device.

Limitations
The PoC uses 5 benchmark runs and is intended only for feasibility
validation.
Final experiments will use the finalized experimental repetition and
statistical-analysis methodology.
The energy model is mathematical and does not directly measure
physical current from a hardware device.
The deterministic nonce strategy used by the PoC script is for testing
only and must not be used in production.
The generated results/energy_model_poc.json is currently ignored by
the repository's results/* Git policy.
Reproduction

Run from the project root with the project virtual environment enabled:

python -m scripts.test_energy_model

The script prints the measured payload size, Secure Packet size,
processing time, energy components, and validation status.
